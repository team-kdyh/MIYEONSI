# AC 2 — 직장 미션 검증

실행일: 2026-11-21. 이 문서는 직장 모드 AC 2의 구현과 검증 범위만 다룬다. 전체 게임의 상용 준비 완료를 주장하지 않는다.

## 구현

`server/office.ts`가 8개 미션의 도입, 현재 반론, 시간·책임·권한 조건, 허용 타협, 실패 조건, 턴 제한, 세 결말을 소유한다. `MissionAgreement`에는 실제 확보한 조건과 버전, `PersuasionEvidence[]`에는 입력 원문, 대상 조건, 근거/대안/경계 구분, 대응 반론, 의미 중복 키, 유효성, 적용 전후 변화가 저장된다.

모든 필수 조건을 확보하면 성공한다. 종료 입력 또는 턴 제한에서는 모든 조건이 필수 또는 허용 타협으로 채워졌을 때만 부분성공이다. 하나라도 미확보이면 실패한다. 선택 횟수, 점수, 상사의 호의적 대사는 판정에 쓰지 않는다. 종료 조건의 세 값은 24개의 독립적인 엔딩으로 해금된다.

자유 입력과 제안 답변은 같은 `advanceOffice` 경로로 처리한다. 텍스트가 있으면 버튼 번호보다 우선한다. 현재 반론에 대응하는 서버 규칙만 조건을 바꾼다. 같은 미션/조건/확보값의 의미 키는 표현이나 근거를 바꿔도 중복 진전을 주지 않는다. 중복과 무관한 입력도 협상 턴을 소비한다. 유효한 변경만 사건 식별자·버전을 가진 정본 사실로 기록하며, 모델 대사와 사용자 주장은 별도 원장에 남긴다.

미션 선택 화면과 현재 합의 패널은 조건을 표시한다. 결말은 실제 확보값, 미확보 목표, 설득 과정 및 다시 도전/다른 미션 버튼을 제공한다. 기존 원본 PNG는 수정하지 않았다.

## 입증 범위와 한계

외부 API 호출은 이번 작업에서 **0회**다. 모든 실행은 offline provider와 로컬 HTTP/Chromium으로 검증했다. 실제 OpenAI의 대사 품질·속도·유연한 한국어 이해를 입증하지 않는다. 기존 provider의 제한된 대사 선택 동작은 이 AC에서 수정하지 않았다.

자유 입력 해석은 미션별 어휘·조건 조합과 동의 표현을 인식하는 결정적 규칙이다. 임의의 한국어 문장을 모두 이해하는 범용 의미 모델이 아니다. 지원하는 주장·대안은 `terms[].arguments`와 `offer`에 공개되어 있으며, 인식되지 않는 입력에는 진전을 주지 않고 부족한 연결을 안내한다. 입력의 근거는 게임 속 주장으로 취급하며 실제 고객 메일, 인사 기록, 사내 달력 또는 사용자 기기를 조회하지 않는다. 합의는 허구의 미션 계약에 따른 서버 사건이다.

## 병렬 작업 통합 지점

- `game.ts`: `Game.office?`, `start(mode, mission=0)`, `sceneFor(game)`, office 분기의 `advance`/`view` 위임. 로맨스 분기는 보존했다.
- `dialogue.ts`: office 자유 입력은 `advanceOffice`; 변경된 합의만 정본에 추가. `context`에 미션·합의를 포함한다.
- `index.ts`: `POST /api/new`의 `mission` 선택, 제안 대사 조회에 `sceneFor` 사용. 저장 구현 자체는 변경하지 않았다.
- `main.tsx`: 미션 선택·합의 패널·턴 표시·재도전. `OfficeAgreement.tsx`로 직장 UI를 분리했다.
- 기존 6턴 직장 점수 테스트는 더 이상 계약이 아니므로 직장 전용 테스트로 대체했다. 로맨스 테스트는 유지했다.
