## 결과와 범위

**실행 가능한 Windows 로컬 후보와 AC7의 검증 자료를 제공한다. 상용 출시 보증은 아니다.** 실제 OpenAI 다중 턴 검증은 총 32회 중 24회 저장 성공, 8회 검증 실패였다. 실패 응답과 미확정 상태를 숨기거나 mock으로 대체하지 않았다. 수정 중 여러 코드 버전이 포함돼 있으므로 24/32를 최종 버전의 성공률로 해석해서는 안 된다. 마지막 동일 provider/narrative 구현의 29–32번은 모두 저장 성공했으나 네 표본만으로 일반화할 수 없다.

- 직장 A: 자연스러운 90초 음성 메모·오류 목록·다음날 10시 원격 수정이라는 새 대안 → 인계 합의(04) → 18시 퇴근 합의(05) → 자연 종료 누락 발견(06) → 수정 후 저장 불러오기로 성공 결말(30).
- 직장 B: 동일한 초기 미션에서 담당/퇴근 확답 거절(08) → 고객 연장 요청 제안(09). 합의 미확정과 결말 없음 유지. 초기 게임의 랜덤 ID/시각을 제외한 같은 의미 상태에서 A와 B의 사건이 달라졌다.
- 로맨스: 10,12–18,21,22,24–29,31이 **한 이야기의 17개 성공 턴**이다. 사이 실패는 진행을 저장하지 않았고 7턴의 save/load 및 프로세스 재시작에도 이어졌다. 4개 편안한 첫 대화는 cafe/strangers에 머물렀다. 이후 familiar→attracted→실제 NPC 고백→사용자 명시 수락으로 couple→실제 date 1/rooftop 이동을 확인했다.
- 기억: 17번은 지호/귤 싫음/배 좋아함과 유나의 시나몬 향 취향을 구분했다. 28번은 연인이 된 뒤에도 앞선 목소리 녹음 거절을 기억했다. 31번에서 새 파란 종이 약속이 기존 ID를 참조해 fulfilled로 저장됐다.
- 로맨스 반사실: 32번의 narrative 시작 상태는 **26번의 시작 상태와 동일한 12턴 couple/cafe 저장**이다. 새 데이트 제안 대신 옥상 거절·카페 잔류·이별 거절을 말하자 cafe/couple을 유지하며 녹음기를 넣었다. 29번과 동일 시작 상태인 대조군이라고 주장하지 않는다. 29번의 실제 이동과는 추가 세 턴이 차이 난다.

전체 입력·대사·행동·확정 사건은 [읽기용 전체 기록](v2-live-transcript.md), 기계 판독은 [요약](v2-live-summary.json), 각 `v2-live-01.json`~`v2-live-32.json`에 있다. 각 원본은 입력 전 공개 API 상태, 요청, HTTP 결과, 실제 Responses 원문, 당시 소스 SHA256을 포함한다. 고급 상태 주입·오프라인 접두 대화 없이 공개 new/turn/save/load API로 진행했다. 화면 재생용 응답 mock은 아래 시각 검사에만 사용했다.

## 호출 통제와 모델

[새 원장](v2-api-smoke-ledger.json)은 부모가 공개한 **추가 32회 운영 한도**다. 사용자 지정 금액 예산이 아니다. 이전 [12회 원장](api-smoke-ledger.json)은 변경하지 않았으며 누적 44회다. 모든 요청은 네트워크 전에 예약했다. 실패 01/02/03/07/11/19/20/23도 각각 1회다. 호출당 최대 출력 1600토큰, `store:false`, 공식 `/v1/responses`, strict JSON schema다. 재시도 자동 호출은 없다. 모든 32회가 completed 응답을 받았고 여덟 건은 의미/참조 검증에서 저장되지 않았다.

첫 시도는 기존 `.env` override인 `gpt-4.1-mini-2025-04-14`가 실제 응답했다. 02–32번은 QA 서버에 명시적으로 `gpt-4.1`을 설정했고 실제 `gpt-4.1-2025-04-14` 응답을 보존했다. 앱 기본값과 `.env.example`은 gpt-4.1이다. 최종 로컬 실행도 검증 모델을 사용하도록 개인 `.env`의 모델 항목만 gpt-4.1로 바꿨고 키와 다른 설정은 보존했다. 이 설정 변경으로 추가 호출은 하지 않았다. 원장은 이미 소진됐고 smoke runner는 33번째 시도를 거부한다. API key나 Authorization 헤더는 캡처하지 않는다.

지연 중앙값 2943.5ms, 최댓값 4192ms(전체 32회 로컬 HTTP 시간)였다. 네트워크/부하/긴 게임의 미래 지연을 보장하지 않는다. 무료 테스트의 느린 응답·취소·429·잘못된 구조 검사는 실제 서비스 지연 통계와 분리한다.

독립 담당자가 원문과 실제 PNG를 직접 보고 [응답성/인물성/기억/사건 영향/속도/가독성 비평](v2-independent-critique.md)을 작성했다. 큰 그림과 어두운 하단창은 읽기 쉽지만 작은 화면에서 긴 대사는 창 안에서 스크롤해야 하고 상단 작은 글씨가 복잡하다. 29번은 창 안 마지막 문장이 잘리므로 스크롤 없이 긴 대사 전체를 읽는다고 주장하지 않는다. 얼굴과 입력은 계속 보인다.

인물별 실제12그림과6개 배경은 [AC4 기록](v2-ac4-verification.md), 8곡의 파일·서로 다른 악보/편성·길이·해시·재생 및6개 전환은 [AC5 기록](v2-ac5-verification.md), `v2-audio-*-path.json`을 참조한다. 포즈 전환·effects reduction·최소8초 음악 유지/2초 fade·음소거/음량 저장을 브라우저에서 재검증했다. 실제 AI 표본에서 모든12포즈/모든8곡을 자연 발생시킨 것은 아니다. 음원 디코딩과 브라우저 currentTime 증가는 확인했지만 사람의 감상 품질 판정은 하지 않았다.

## 출처와 남은 한계

2026-11-21 공식 페이지를 다시 확인했다. [DDLC Plus](https://ddlc.plus/)의 Full HD 인물 무대와 다양한 음악 소개에서 지속되는 장면과 음악 리듬을 참고했다. [Toptoon Chat](https://chat.toptoon.com/)의 실시간 캐릭터 대화 소개에서 인물 중심의 입력 경험을 참고했다. 이는 설계 해석이며 로그인 서비스 내부 기억 성능을 시험한 것이 아니다. 인물·대사·그림·음악을 복제하지 않았다. [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)의 strict schema/anyOf를 활용하지만 구조 적합성이 이야기의 의미적 정확성을 보장하지 않는다는 점은 이번 실패에서도 드러났다. 자산 provenance는 README에 연결한 원본 manifest에 있다.

1. **31번의 “파란 종이 받아서”는 유나가 준 종이를 받은 것처럼 말하는 남은 주체 오류다.** 저장된 promise 주체는 npc로 맞지만 대사 오류가 없어지는 것은 아니다. 32회 한도를 소진해 추가 실호출 수정 검증을 주장하지 않는다.
2. 모델은 사건을 빠뜨리거나 부적절한 사건을 제안할 수 있고 서버는 실패 시 턴 전체를 보존하지 않는다. 마지막 수리 후 같은 실패를 보지 않았다는 사실만으로 모든 표현이 작동한다고 할 수 없다. 어떤 약속은 invitation/promise 중복으로 남았다.
3. 실제 paid 검증은 직장 1미션의 대조 흐름과 로맨스 연인/데이트까지다. 나머지7미션과 archive 스릴러/4개 결말은 의미 있는 deterministic 검증이 있으나 실제 대화 완주 품질은 미검증이다. AC3 전체 실제 품질 승인을 대신하지 않는다.
4. 한 이야기를 여러 수정 버전에 걸쳐 진행했다. 새 기본 버전으로 처음부터 끝까지 다시 한 frozen-version live run은 없다. 실제 모델 접근과 마지막 개선은 근거가 있으나 미래 제공자/모델 변경에 대한 보증은 아니다.
5. 음악의 사람 청취·장기 몰입감·모든 표현/기기·상업 법률/배포 심사는 범위 밖이다. 로컬 실행 패키지의 기술적 전달과 관찰 보고를 완성했으며 전반적 상품성은 추가 사람 플레이테스트가 필요하다.

키·개인 저장을 제외한 ZIP 및 검사 기록은 `v2-package-audit.json`으로 확인한다. 원본 에셋·라이선스·v1 증거와 저장은 보존했다. 공개 호스팅이나 타인에게 메시지는 보내지 않았다.
