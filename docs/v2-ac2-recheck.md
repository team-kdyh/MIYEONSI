## 재현과 수정

부모의 `post-live32` 후보를 읽고 narrative/provider/dialogue의 기준 SHA256이 현재 파일과 일치함을 확인했다. 먼저 48개 회귀 테스트를 현재 구현에 적용해 **31 통과 / 17 실패**를 재현했다 (`v2-ac2-agency-before.tap`). 이후 해당 narrative 패치와 거절 기록 계약 테스트를 통합했다. 거절 테스트는 삭제하지 않고 관계·데이트 수 유지 및 거절 기록을 검사하도록 바꿨다.

- 인용된 대사, 질문, 명시적 철회를 플레이어의 합의로 확정하지 않는다.
- 이별 거절과 미래 관계 제안은 기록하되 관계/데이트 달성으로 반영하지 않는다.
- 이름·호칭으로 지칭된 플레이어 행동과 생각을 NPC 행동 채널에서 차단한다. NPC가 플레이어의 손을 바라보는 동작은 허용한다.
- 동일 기억과 약속의 재확인은 중복 사실을 만들지 않는다. 다른 장소를 거친 귀환 이동은 실제 새 이동으로 기록한다.
- 추가 검사에서 “음…”, “글쎄요”, “잘 모르겠어요”, “생각해 볼게요”가 잘못 수락되던 네 실패를 재현하고 비확정 표현 가드를 보강했다 (`v2-ac2-ambiguous-before.tap`). 최종 관련 검사는 **53/53**이다.

## 분기와 지속성

`server/narrative-counterfactual.test.ts`는 공개 new 처리와 같은 초기 정규화를 한 상태를 디스크에 저장한다. 각 분기는 그 저장을 새 ProfileStore로 읽고 시작한다. 분기별 시작 SHA256은 같다. 직장에서는 합의 완료 / 새 범위 제안 / 인계 거절, 로맨스에서는 옥상 / 강변 대안 / 카페 잔류를 비교한다.

각 분기 뒤 동일한 후속 입력을 보내고 자동 저장 및 슬롯 저장을 수행한 다음 새 ProfileStore로 복원하고 다시 동일 후속 입력을 보낸다. 문구나 로그를 제외한 합의·장소·관계·데이트·결말 상태를 비교해 세 분기의 차이가 유지됨을 확인한다. 직장에서는 동일 성공 결말 제안이 필수 합의를 완료한 분기에서만 승인되고 다른 두 분기에서 거부된다.

전체 상태와 입력, 응답 fixture, 공통 후속 입력, 복원 상태는 `v2-ac2-office-durable-counterfactual.json`과 `v2-ac2-romance-durable-counterfactual.json`에 있다. **이 검사는 생성 응답을 고정한 결정론적 검증이다. 새로운 실제 OpenAI 분기 대화 증거가 아니다.** 최초 테스트 작성 시 dialogue 초기화를 빠뜨려 저장 검증이 실패했고, 공개 new 처리와 동일하게 canonical/narrative 초기화를 추가했다. 제품 저장 검증은 변경하지 않았다.

## 남은 승인 범위

이 수정은 결정론적으로 재현된 결함을 해결했지만 AC 2 전체의 실제 모델 분기 검증을 완료했다고 판정하지 않는다. 기존 실대화 직장 A/B는 의미상 같은 초기 상태이고, 로맨스 26/32는 정확히 같은 시작 상태이나 세 대안 모두와 공통 후속 입력·저장 복원 이후까지 이어지는 실제 생성 비교는 없다. 새 결정론적 검사를 그 실대화 증거로 대신하지 않는다.

후속 실제 생성 검증에는 최종 conversational-QA 담당자와 새로 승인된 운영 한도가 필요하다. 현재 한도를 임의로 늘리거나 원장을 초기화하지 않았다. 자연어 가드는 제한된 패턴이며 임의 한국어 의미 판단 전체를 보장하지 않는다. 원본 16번 대사의 과거 착석 날조 및 31번 전달 주체 표현 문제도 이번 action/event 가드로 수정됐다고 주장하지 않는다. provider 프롬프트 및 실제 응답은 그대로 보존했다. 새로운 reducer 때문에 기존 릴리스 패키지/전체 QA 소스 해시는 현 구현의 검증 자료로 재사용할 수 없으며, 최종 패키징 담당자는 이 변경을 포함해 다시 패키징해야 한다.
