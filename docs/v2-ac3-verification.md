# v2 AC3 — 이야기 진행 및 협상 검증

2026-11-21. 이 작업은 기존 Ralph 실행의 AC3 구현 단계다. 중첩 auto/새 세션/세션 signal 및 유료 Responses 호출은 실행하지 않았다. v1 원장·실호출 증거와 플레이어 저장 파일은 수정하지 않았다.

## 발견하고 수정한 결함

- 이전 v2는 여덟 직장 미션 모두 `scope/owner/deadline/boundary` 네 태그로 결말을 열었다. 공로 정정 같은 미션도 무관한 업무 인계만으로 완료될 수 있었다. 이제 현재 미션의 실제 목표 ID 전부에 대한 이전 턴의 합의가 필요하다. 중간 계획 태그는 보존하지만 목표 충족을 대신하지 않는다.
- provider 문맥에 미션별 목표 ID, 고유 반론, 원래의 유머 있는 도입을 제공한다. 고정 정답/예시 문구는 제공하지 않는다. 새로운 날짜·담당자·비동기 회의·녹화 인계·출처 링크 등도 목표별 합의로 남는다. 장면 이동이나 결말에는 턴 상한이 없다.
- 결별 이후 반복/재설정/복원 결말이 가능하던 경로를 닫았다. 한 턴에 관계 사건은 하나만 승인하며, 거절 상태를 호감으로 처리하거나 같은 턴에 연인·데이트를 확정할 수 없다. 종료된 게임에 추가 사건을 넣을 수 없다.
- 복원 결말은 서로 다른 두 단서의 검증을 요구한다. 같은 단서를 문구만 바꿔 두 번 제시해도 복원 자격을 얻지 못한다.
- 긍정적인 업무 경계를 부정어 때문에 거절하던 문제를 보완했다. 예: 회식 불참 불이익 없음, 주말에는 일하지 않겠다는 합의. 일반 업무 제안의 철회는 계속 거부한다.
- 최초 로맨스 소개가 플레이어의 헤드폰 줄 풀기 행동을 지어내던 문장을 유나 자신의 행동으로 수정했다.
- 대화 지침에 실제 취향/약속에서 나온 데이트, 과거 실제 발화의 편집, 편집 책임 대면, 네 결말의 서로 다른 결과를 명시했다. 이것은 모델 품질의 관측 증거가 아니라 구현 지침이다.

## 검증

`server/v2-story.test.ts`는 정상 새 게임에서 여덟 미션의 새로운 계획, 각 목표가 없을 때 결말 거부, 5턴 잡담 유지, 네 로맨스 결말, 거절 후 5턴 관계 유지, 중복 단서 및 단계 건너뛰기 거부를 검사한다. `server/narrative.test.ts`는 10턴의 주체별 새 호칭/과일 취향/약속이 3슬롯 저장과 새 ProfileStore 복원 뒤 이행 사건으로 반영됨을 검사한다. 기존 자유 사건·모의 Responses·보안·저장 회귀도 유지했다.

- `npm run build`: 통과 (타입 검사 포함). `v2-ac3-build-run.txt`.
- `npm test`: 134/134 통과, 실패·건너뜀 0. 결과는 `v2-ac3-unit-run.txt`에 보존한다.
- 유료 API 호출: 0회. 기존 원장 변경 없음.
- 화면 변경은 이 AC의 범위가 아니다. 동시 진행 중인 에셋·표시 파일은 수정하지 않았다.

## 최종 대화 QA 전달 / 남은 한계

AC3 구현 및 결정적 검사는 완료했지만 **실제 모델 대화 품질까지 포함한 최종 AC 승인은 보류**한다. 최종 QA 소유자는 새 구현 해시로 승인된 원장에 먼저 예약하고 실대화를 확인해야 한다. 특히 (1) mission objectives의 ID로 합의를 제안하는지, (2) 합리적인 새 대안에 저항 후 양보하는지, (3) 이름·취향·약속의 10턴 실제 회상과 사건 결과, (4) 따뜻한 고백/데이트 뒤 편집 집착으로 넘어가는 자연스러운 속도를 검토해야 한다. 이 단계의 mock 대사를 실제 챗봇 성공으로 해석하지 않는다.

서버는 구조·근거 인용·관계 순서·목표 태그·단서 구별을 검증한다. 자유 문장의 의미가 해당 목표 전체를 정말 충족하는지, 새 단서 둘이 의미적으로 독립적인지에는 모델 판단이 관여한다. 임의 한국어 전체의 의미 정확성이나 재미를 자동 검사만으로 보장하지 않는다. 모델이 부적합한 사건을 내면 원자적으로 거부하고 저장하지 않는 기존 재시도 동작을 유지한다.
