# AC4 재검증 — 2026-11-21

범위: 두 캐릭터의 실제 일러스트 상태, 배경, 제안과 확정 행동의 시각 경계. 다른 AC나 출시 후보 전체의 완료 판정은 아니다.

## 수정한 결함

1. 기존 모바일 캡처에서 부장의 `smile`과 `farewell`을 구분하는 허리에 댄 손, 유나 `shy`의 낮게 모은 손이 대화창 아래로 가려졌다. 데스크톱/모바일의 기본 구도를 조정해 원본 셀 높이 92%까지 대화창 위에 노출한다. 얼굴뿐 아니라 손과 팔의 차이를 실제 플레이 화면에서 읽을 수 있다. 동일 인물의 크기/위치 변경을 별도 상태로 세지 않는다.
2. 모바일에서 구도를 조정한 뒤 장면 제목이 머리와 겹쳤다. 작은 장면 제목을 상단 한 줄로 정리했다. 배경은 여전히 전체 화면이며 하단 대화창은 그대로 유지한다.
3. 실제 응답 26의 종이배 건네기에 `offer`를 그대로 사용하면 헤드폰이 나타났고, 응답 28의 녹음기 수납에 `concern`을 그대로 사용하면 녹음기를 계속 안고 있었다. `presentationPose`는 현재 행동 지문에 헤드폰/테이프가 없는 경우 소품 없는 자세를 사용하며, 녹음기를 넣은 뒤에는 손목을 감싼 자세로 표시한다. 서사 상태나 모델 원본 응답은 변경하지 않는다. 필요한 소품이 명시된 행동에서는 원래 자세를 유지한다. 이는 관찰된 소품 세 종류에 대한 방어이며 모든 한국어 동작을 이해하는 의미 판정기는 아니다.

## 제안과 확정 상태의 화면 연결

`tests/v2-ac4-boundaries.spec.ts`는 실제 `reconcile`로 생성한 상태를 UI에 전달한다. 모델만 고정 fixture다. 1440×900 / 390×844, 기본 효과 / 효과 감소의 네 경로마다 아래 흐름의 응답·이전/이후 상태·사건 ID·스크린샷을 `v2-ac4-boundaries-*.json`에 기록한다.

- 옥상 초대 미수락 → 거절: 카페 유지. NPC가 제안하는 손짓은 가능하지만 이동은 표시하지 않는다.
- 명시적 현재 이동 수락: `move` 확정 사건과 함께 옥상으로 전환.
- 호감과 고백 → 연인 제안 미수락 → 거절: 관계는 `confessed` 유지. 명시적 수락 이후에만 `couple`.
- 데이트 제안 → 거절 → 내일 약속 수락: 장소/데이트 완료 횟수는 유지하고 현재 참여도 시작하지 않는다.
- 오늘 현재 장소에서 데이트 수락: `activeDate`만 생성, 완료 횟수 0. 후속 턴에서 근거 있는 실제 공동 활동을 확인한 뒤 완료 1.

모든 행동 지문은 NPC의 몸짓이다. 플레이어의 손잡기·이동·상호 접촉을 그림으로 선행 표현하지 않는다. 효과 감소에서는 입장/배경 교차 애니메이션을 생략하되 같은 확정 배경·인물·포즈·행동 지문을 표시한다. 일반 효과에서는 턴별 입장이 한 번 실행되고 정지한다. 옥상과 빗길 두 신규 배경의 실제 표시도 전체 자세 검사에서 확인한다.

## 검증의 종류와 한계

- 자세 전체 검사는 고정 응답 + 실제 서버 판정 + 실제 브라우저 렌더링이다. 12개의 모든 자세를 모델이 실제로 선택했다는 주장은 하지 않는다.
- 실제 유료 호출로 이미 확보된 응답 4/5/6/12/26/28/29/32는 원본 상태 그대로 현재 UI에서 다시 렌더링한다. 결과는 `v2-ac4-captured-{1440,390}.json`. 모델이 생성한 서로 다른 반응의 자세 변경, 카페→옥상→카페와 행동 지문, 소품 불일치 수정 확인에 사용한다. 새 실호출 증거가 아니다.
- 추가 유료 호출 0. 기존 12회와 v2 32회 원장, 개인 저장 데이터, 기존 증거를 보존했다. provider/서사 판정 소스는 이번 AC에서 변경하지 않았다.
- 첫 구도 검사의 데스크톱 손 가림 실패는 `v2-ac4-recheck-initial-failure.txt`에 보존했다. 후속 실행 도중 소스 편집으로 Vite가 페이지를 다시 불러와 두 검사가 중단된 결과는 `v2-ac4-hmr-interrupted-run.txt`에 남겼으며, 최종 검사는 소스를 고정한 뒤 다시 실행했다. 기준을 완화하지 않았다.

최종 명령 결과는 `v2-ac4-recheck-browser.txt`, `v2-ac4-recheck-build.txt`, `v2-ac4-recheck-unit.txt`, `v2-ac4-ui-regression.txt`에, 검증 대상 해시는 `v2-ac4-recheck-hashes.json`에 기록한다. 전체 출시·대화 품질 판정과 기존 AC2/AC3의 실호출 범위 제한은 별개다.

최종 결과: **AC4 완료**. 빌드/타입 검사 통과, 전체 단위 검사 **211/211**, AC4 브라우저 **11/11**, 기존 UI 브라우저 **4/4** 통과. 최종 두 비교 PNG의 24개 상태를 직접 열어 확인했다. 부장의 팔짱 두 상태는 턱/시선과 팔 각도가 다르고, 안경 동작 두 상태는 반대 손이 다르며, 미소/양보는 허리 손이 구분된다. 유나의 모든 상태는 얼굴·손·상체 차이가 읽힌다. 확대된 얼굴 위주 구도보다 인물이 작아진 대신 실제 손동작과 배경을 함께 읽을 수 있다.
