# C안 — 승인 전, 추가 호출 0회

기존 `.ralph/v2-review/final-live-plan.md` 원문을 수정하지 않는 보조안이다. 사용자 추가 승인은 아직 없으며 실제 승인 후 부모가 선택한다. 24회는 성공 횟수가 아니라 실패를 포함한 최대 예약/시도 수다.

| 묶음 | 최대 시도 | 경로 |
| --- | ---: | --- |
| 직장 동일 시작 A/B | 4 | A 새로운 대안 1턴 → 저장/불러오기 → 공통 후속 1턴; 초기 슬롯 복원 후 B 거절 1턴 → 저장/불러오기 → 같은 공통 후속 1턴 |
| 완전한 새 로맨스 | 14 | 앞 계획의 이름/취향/제3자 구분, 새 약속, 거절, 상호 고백, 데이트, 자연스러운 후반부를 실제 응답에 맞춰 한 턴씩 선택 |
| 같은 couple 저장에서 거절 대조 | 2 | 새 로맨스에서 실제 couple이 된 저장을 복원 → 녹음/초대 한 가지를 명확히 거절 1턴 → 본 경로와 같은 후속 질문 1턴 |
| 예비 | 4 | 재현된 실패의 무료 분석/수정 후 필요한 재검증에만 배정 |
| 합계 | 24 | 자동 소비하지 않음 |

직장 공통 후속 예: “지금 제가 맡기로 한 일과 아직 맡기로 하지 않은 일을 구분해 주세요. 담당자와 확인 시점도 실제 합의된 것만 알려 주세요.” 최초 대안과 거절의 입력은 기존 계획의 A/B 재료를 사용하되 부장 답변에 따라 자연스럽게 정한다. 이 4회 구성은 양쪽의 상태/기억 차이를 검사하며, 별도 마무리 턴이 없으므로 성공 엔딩 관찰을 보장하지 않는다.

로맨스에서 couple 상태가 실제로 생겼을 때 **14회 본 경로 안에서** 그 상태를 public slot에 저장하고, 같은 지점의 본 경로에서 공통 후속 한 번을 계획한다. 이후 2회 분기는 그 동일 저장을 복원해 “오늘 제 목소리는 녹음하지 말아 주세요. 지금은 카페에 더 있고 싶어요.”처럼 자기 경계를 말한 뒤, 본 경로와 **정확히 같은 후속 문장**을 쓴다. 예: “지금 우리 사이에서 정한 것과 아직 정하지 않은 것을 기억나는 대로 말해 줄래요?” 새 refusal가 기존 연인 관계·취향·약속 전체를 지우거나 과거 동의로 바뀌지 않는지 본다.

본 경로에 같은 후속을 넣지 못했다면 이 2회는 동일 조건 A/B 검증이라고 부르지 않는다. couple 저장이 14회 안에 생기지 않으면 JSON 주입이나 과거 기록 재분류로 대신하지 않고 그 범위를 미검증으로 남긴다. 14회 안에 데이트/스릴러/결말을 모두 요구하거나 한 입력에 사건을 몰아넣지 않는다. 예비 4회를 자동으로 소모해 계획을 맞추지 않는다.

각 분기의 정상 public 저장·불러오기 기록, source/model hash, before/input/raw/after를 연결한다. 브랜치 성공 수를 하나의 연속 플레이로 합산하지 않으며, 새 로맨스의 연속 10턴·실제 데이트·후반 arc 증거를 따로 판정한다.
